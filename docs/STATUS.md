# Feature status

See [KERNEL_AUDIT.md](KERNEL_AUDIT.md) for subsystem classifications, evidence,
test results, and the dependency-ordered next milestones.

## Implemented and QEMU exercised

- Limine x86-64 boot, serial diagnostics, GDT/TSS, exception IDT, and panic reporting.
- CPU hardening enables CR0.WP and CPUID-gated SMEP, SMAP, and UMIP; user memory uses interrupt-safe, SMAP-aware copy helpers.
- NX is required at boot so kernel and user page protections can enforce W^X consistently.
- PMM, four-level VMM, candidate kernel address space, W^X kernel sections, HHDM and boot-resource cloning.
- Opt-in CR3 round-trip with continuation checks and assembly rollback; normal boot permanently activates the candidate root.
- KVA and hardened kernel heap with allocation, free, splitting, coalescing, 16-byte alignment, per-block header validation and redzones, freed-payload poisoning, and guarded stack mappings. Invalid non-KVA pointers are rejected before allocator metadata is read.
- Interrupt-safe allocator locks serialize PMM bitmap mutations, KVA mappings, heap metadata, and process-table lifecycle updates on the current CPU.
- ACPI MADT discovery, xAPIC/x2APIC local-controller access, IOAPIC setup, timer interrupts, checked PS/2 keyboard and mouse initialization, a shared keyboard/pointer event queue, framebuffer pointer rendering, optional interrupt-driven 16550 serial receive with a polling fallback, and ACPI S5 poweroff through FADT/DSDT PM1 controls.
- Single-core round-robin scheduler with APIC timer preemption, cooperative yield, deadline-based sleeping, intrusive wait queues with atomic block/wakeup, event-driven terminal input, an HLT idle task, task exit, and deferred task/stack reclamation.
- Limine RGB framebuffer discovery and a checked 24/32-bit renderer with clipped rectangle fills, 8x8 bitmap text, scrolling, clear, cursor positioning, and a 16-color boot pattern. 32-bit fills batch pixels with SSE2 while saving/restoring the caller's FPU state. Kernel and terminal output is mirrored to the framebuffer and serial; the framebuffer accepts basic ANSI 16-color SGR and clear/cursor sequences.
- Early x86 PCI configuration-mechanism-1 enumeration scans all 256 bus numbers, honors multifunction headers, records bounded vendor/device/class data, and reports common storage, network, display, USB, and bridge classes.
- VMware Workstation Player 17 profile boots the shell-first EFI ISO to `ANIX_BOOT_OK` and a visible ring-3 shell prompt; VMware virtual PCI functions and firmware framebuffer are discovered successfully. This verifies VMware's emulated PS/2 path, not physical laptop compatibility.
- PID 1 adopts live and exited descendants when their intermediate parent exits; QEMU verifies the adopted process observes PPID 1 and PID 1 reaps it with `waitpid(-1)`.
- CPU-gated x87/SSE2 enablement and per-task FXSAVE/FXRSTOR state; the SDK QEMU workload switches between tasks while preserving distinct XMM values.
- Scheduler task and interrupt stacks have unmapped guard pages; QEMU checks the guards and requires a timer-preemption sentinel.
- Boot orchestration is split from platform setup and memory self-tests in `kernel/platform.c` and `kernel/selftest.c`.
- User syscall dispatch now lives in `syscall/dispatch.c`; ELF loading and process address-space lifecycle remain in `userspace/elf.c`, with their private process structures and helper contract in `userspace/internal.h`.
- Newc CPIO initramfs and path-based VFS lookup, listing, and file reads; userspace can create volatile directories and bounded regular files beneath `/tmp`, while the initramfs tree remains read-only. Open unlinked files remain alive until the final descriptor closes. The SDK/QEMU boot check exercises nested create, write, read, listing, and unlink.
- Generic bounded block-device registry, legacy ATA PIO LBA28 primary-master driver, and checked MBR primary-partition discovery with bounded translated block views; PCI enumeration currently discovers hardware but does not yet bind PCI class drivers. QEMU verifies partition-backed AnixFS I/O and disk persistence.
- AnixFS v1 fixed-slot disk filesystem mounted at `/persist` from an MBR primary partition or, for compatibility, a whole-disk volume, with backward-compatible file and directory entry records; nested persistent directories and files can be created, listed, read, unlinked, and removed when empty.
- User ELF64 loading into per-process address spaces with W^X segment validation, bounded user-memory checks, ring 3 entry, `init` → SDK app → `anixsh`, user-fault recovery, and process-page cleanup on exit and successful transactional exec replacement. Exit becomes visible only after the task wrapper completes resource cleanup and child adoption, preventing `waitpid` from reclaiming a record still in use. QEMU checks failed-exec preservation, then execs a second image linked at the same virtual address and verifies arguments, environment, and preserved shell startup.
- Per-process `sbrk` heap growth and shrink with writable NX mappings, page reclamation, zero-on-regrowth, and user/stack collision bounds; the SDK example exercises multi-page growth, yield preservation, shrink, and zeroed regrowth.
- SDK `anix_malloc`/`anix_free`/`anix_calloc`/`anix_realloc` runtime with aligned blocks, checked size arithmetic, splitting, coalescing, invalid-pointer rejection, and trailing-break reclamation; QEMU exercises reuse, coalescing, resize preservation, zeroing, and full release.
- SDK descriptor-based `anix_printf`/`anix_fprintf` formatting and bounded `anix_getline` support; QEMU verifies string, signed, unsigned hex, width/zero-padding, character and escaped-percent formatting, while the opt-in stdin workload checks the line helper after partial raw reads.
- SDK `anix_stat` syscall exposes stable node type, regular-file size, writable and persistent metadata; QEMU checks regular files, directories, permissions, sizes, missing paths, and `/persist` metadata when the ATA volume is mounted.
- ELF entry stacks use the conventional `argc`/`argv`/`envp` layout. The original path-only launchers use the executable path for `argv[0]`; additive `execv`/`spawnv` syscalls copy caller-supplied vectors with bounds of 16 strings, 127 bytes per string. QEMU checks arguments and environment transfer through both syscalls.
- Versioned, documented userspace syscall ABI for standard descriptor `read`/`write`, compatible `readline`/`write_file`, ticks, `getpid`/`getppid`/sleep, exec/execv/exit, direct-child spawn/spawnv/wait/waitpid, anonymous pipe creation, per-process chdir/getcwd and relative path resolution, VFS open/read/close/list/stat/create/mkdir/rmdir/seek/unlink, writable/append/truncate opens, descriptor duplication and `dup2` standard-stream redirection, and cooperative yield. QEMU checks timed sleeping and deadline order, process identity and orphan parent detachment, line-oriented stdin including preserved partial reads, file writes through ordinary `write(fd, ...)`, argument/environment transfer, blocked and already-exited waitpid paths, pipe reader/writer blocking and wakeup, backpressure, close-driven EOF, broken writes after the final reader closes, directory removal constraints, current-directory inheritance, volatile append, persistent rewrite across reboot, process-slot reuse, child waits, and orphan cleanup.
- Blocking `read_char` syscall lets ring-3 terminal programs implement interactive character-based editing; the SDK shell uses it for command-name Tab cycling while the existing line-based `readline` remains supported.
- Blocking `input_event` syscall exposes keyboard press/release, modifier, pointer-coordinate, motion, and button events through the public SDK ABI; the current PS/2 keyboard and mouse drivers feed the same bounded event queue.
- Spawned users inherit reference-counted open-file descriptions, sharing file offsets and flags. QEMU checks a child reading through an inherited descriptor, the parent's observing the shared offset afterward, and the child closing its reference without invalidating the parent's descriptor.
- Process groups are tracked per process, inherited by spawned children, and exposed through checked `getpgid`/`setpgid` syscalls. A process can create its own group; a parent can inspect its direct child and move it into a group represented by itself or one of its children. A small `no_std` Rust policy module validates group changes, with host unit tests and a ring-3 QEMU test covering inheritance and regrouping.
- SDK `anix_dup` allocates the lowest available descriptor for standard streams and open files; duplicated file handles share the same offset, and QEMU checks serial output duplication, opt-in terminal-input duplication, shared file offsets, and independent close lifetime.
- User-space shell commands: `help`, `ticks`, `status`, `pwd`, `cd`, `ls`, multi-file `cat`, quoted/escaped `echo`, `clear`, `uname`, `shutdown [--now]`, and `exit`; shutdown requests ACPI S5 poweroff, Tab cycles matching command names, and the command parser rejects unmatched quotes and excess arguments.
- Host tests, QEMU boot smoke test, opt-in CR3 test, and interactive serial checks for shell, file listing/read, process exit, and task reaping.

## Current limitations

- Scheduler and process model are single-core. Process records are bounded to 32 and each process has one task, so its child-event queue currently has at most one blocked waiter. PID 1 adopts orphaned descendants while it is alive; after PID 1 exits, remaining descendants are detached and self-reap on exit. Basic process-group inheritance and `getpgid`/`setpgid` are implemented, but sessions, signals, process-group-wide events, per-process kernel threads, and SMP locks are not.
- User ELF loader supports static, non-PIE ELF64 `ET_EXEC` images and does not yet provide dynamic linking or demand paging. `execv`/`spawnv` have bounded vectors and do not yet expose a POSIX libc. x87 and SSE2 state is scheduled per task; AVX/XSAVE state is not enabled, so SDK applications should target the x86-64 baseline and avoid AVX.
- Syscalls use an `int 0x80` gate; the detected `SYSCALL` instruction is not configured for userspace entry.
- The CPIO tree is read-only except for volatile directories and files beneath `/tmp`. AnixFS v1 supports 64 file/directory records and files up to 64 KiB on an ATA LBA28 volume; it is project-specific, partition discovery supports MBR primary entries only (no GPT or extended-partition traversal), and it has no journal, AHCI, NVMe, or initramfs decompression. Only the primary-master ATA device is probed.
- Keyboard input currently uses PS/2. Mouse hardware and pointer display are disabled by default in shell mode and require the opt-in `ANIX_ENABLE_DESKTOP=1` build; there is no window manager yet. There is no USB HID/xHCI driver, so laptops that expose keyboards only through USB will lack local input. The framebuffer is the firmware-provided GOP/Limine surface; there is no native GPU/virtio driver, hardware acceleration, touchpad, Wi-Fi, or broad laptop power-management support.
- No AP startup, SMP, signals, shared-memory/message-queue IPC, networking, or device hotplug; anonymous pipes are the only IPC primitive. PCI configuration currently uses legacy mechanism 1 and does not yet use ACPI MCFG/PCIe ECAM. APIC/IOAPIC initialization and single-core timer/input routing are implemented.

## Remaining roadmap

- Broader process lifecycle support beyond direct-child wait, including sessions, signals, and process-group-wide events.
- USB HID/xHCI keyboard and mouse drivers, modern input device enumeration, and broader laptop support.
- GPT and extended-partition traversal, stronger crash consistency, and AHCI/NVMe block drivers.
- Broader syscall/ELF support, signals, additional IPC primitives, and user utilities.
- SMP and broader hardware coverage.
